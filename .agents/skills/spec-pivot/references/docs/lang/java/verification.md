# Java: 検証器

## 移植元として

原典と `SourceModel` の一致は、次の決定論的な手段で確認する。原典に検証器を当てることは求めない。原典の規模とフレームワークへの依存の大きさから、現実的でないためである。

| 手段 | 何を確かめるか | 保証の限界 |
| --- | --- | --- |
| 原典実行（[harness.md](harness.md)）: 原典のコードを実行し、`source-model/` のベクタと照合する | ドメイン層の計算・サービスの振る舞いが `SourceModel` と一致する | ベクタの入力の外は保証しない |
| HTTP レベルの原典実行: フレームワークを起動した原典（例: Spring の MockMvc）に要求を送り、応答を照合する | フレームワークの暗黙の処理（入力の変換・検証・セキュリティ・シリアライズ）の写しが一致する | ベクタの入力の外。起動できない構成（外部の DB・キュー・メール）は保証しない |
| 差分の原典実行（版上げ時）: 新旧 2 版の原典を同じ入力で実行する | 版上げで振る舞いが変わった入力を検出する | ベクタの入力の外の変化は検出しない |
| 意味論の突き合わせ: `LangSemantics.Java` の演算と、JVM の実行結果を突き合わせる（例: double はビット単位） | 言語の意味論の写しが一致する | 突き合わせた入力の範囲。`BigDecimal`・`String`・`LocalDate` は、写した演算ごとに突き合わせを用意する |

- 原典実行で実行できない部分（時計を固定できない操作など）は、保証の限界として列挙する。
- 原典にすでに JML などの検証済みの契約があっても、その事後条件をリファインメント定理の仮定として使ってはならない。主定理の仮定は、PRE・INV・`@[deviation]` だけである。既存の検証は、原典実行と同じく補助の手段として扱い、その範囲を限界の文書に書く。

## 移植先として

Java のコードと、Lean `TargetModel` の Java での写しとの一致を確認する手段は次のとおり。

| 手段 | 用途 |
| --- | --- |
| JML ＋ OpenJML（または KeY） | 純粋なメソッドの事前・事後条件を JML で書き、`TargetModel` の写し（JML のモデルメソッド）との一致を検証する |
| jqwik などの性質テスト | 検証器で扱いにくい部分の補助 |
| JUnit の照合テスト | `target-model/`・`shared/` のベクタ（必須） |

> **未整備:** JML の写しの書き方、追跡タグ（`trace: models …`）の置き場所、OpenJML の版固定。Java を移植先にするときに [layout.md](layout.md) とあわせて整備する。
