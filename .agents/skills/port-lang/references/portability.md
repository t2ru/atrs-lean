# 言語中立性の制約（Spec に課す）

`Spec` は、あらゆる移植先言語へ同一の振る舞いを写せるように、次の制約を満たさなければならない。
`SourceModel` / `TargetModel` は言語の意味論を再現するためにこれらを破ってよい。その場合も、演算は `LangSemantics.<lang>` の名前付き演算として、**どの言語でも整数演算だけでエミュレートできる形** で定義する。

## 数値

- **任意精度整数** の意味で定義する。固定長整数で実装する言語のために、値域（オーバーフローしない上限）を明記する。
- 浮動小数点数・10 進小数型を使ってはならない。
- 除算は `floorDiv` / `ceilDiv` を明示し、被除数・除数の符号を事前条件で定める。言語既定の `/` や `%` の丸め方向に依存してはならない。
- 百分率は整数（30 は 30%）で保持し、`* rate / 100` の順序と丸めを明記する。
- 金額・人数・日数など非負が保証される量は自然数、符号を持つ中間値だけ整数とする。

## 文字列

- 文字列は Unicode スカラ値の列とする。長さ・添字はスカラ値単位。
- 文字クラスは **コードポイント範囲の集合** として定義する。正規表現の方言（`\d` や `\w` の意味、Unicode フラグ）に依存してはならない。
- 大文字小文字変換・正規化（NFC 等）・照合順序・ロケール依存の書式を使ってはならない。比較はスカラ値ごとの完全一致のみ。
- 数値の書式化（3 桁区切りなど）は手順として定義する。

## 日付・時刻

- 日付はタイムゾーンを持たない暦日（先発グレゴリオ暦）。時刻は時・分（必要なら秒）。
- 「今日」「現在時刻」を暗黙に取得してはならない。必ず入力（Clock ポート）として受け取る。
- 書式（`yyyy/MM/dd` 等）はゼロ埋め固定桁として定義する。

## 集合・順序

- ハッシュ表・集合の反復順序に依存してはならない。出力に順序がある場合は、並び替えキーと同順位の扱いを明記する。
- 移植元で順序が未規定の結果（`ORDER BY` が無い取得、同順位の並び）は、`Spec` では不変条件か同順位の規則で一意化し、`SourceModel` では「許される結果の集合」として扱う。

## 副作用とエラー

- 業務ロジックは純粋関数として定義する。I/O・時刻・乱数・採番・永続化はポート経由とする。
- エラーは値（直和型）として返す。例外の有無や伝播規則に依存した定義を書いてはならない。
- 評価順序が結果（どのエラーを返すか）に影響する場合は、順序を明記する。

## 確認方法

- `Spec` の定義が、整数・真偽・文字列（スカラ値列）・暦日・列・レコード・直和だけで書けていることを確認する。
- 適合テストベクタが JSON の基本型（整数・文字列・真偽・null・配列・オブジェクト）だけで表現できることを確認する。
